In briefKısaca

One question, asked with money: a Claude Code setup had eleven plugins enabled, and nobody knew what they cost or whether they helped. So each one was measured instead of argued about.

The setup was first cut from eleven plugins to three, then five configurations were built from the survivors — bare (nothing), hooks, superpowers, modes (the terse caveman + ponytail pair), and full (everything) — and run against the same tasks, same prompts, same repository copies. Grading is automatic and out of the agent's reach: a hidden test suite copied in after the agent exits, and a real Chrome driven over CDP for the website round.

It grew past the original four rounds. Today it stands at 286 graded runs across five task types, every one of them measured on both Sonnet and Opus, plus a separate 21-run round on a real, live production site instead of a toy task. Measurement closed on 2026-08-30: 232 matrix cells, none failed.

  • Prose work: the terse modes win outright — 45% cheaper than a bare config, on both models. The whole saving is the shorter answer, not a smaller prompt.
  • Agentic coding: nearly every configuration loses to bare, by +8% to +97%. A coding task produces a few hundred output tokens, so there is nothing for terseness to compress, while the fixed ruleset is re-read on every turn. The two exceptions in 45 cells are both Opus and both modes — the website round (84) and the second hard bug fix (92) — where terseness cuts the turn count instead of the prose.
  • Quality separated exactly once, and even that did not hold up: one hard bug fix on Sonnet, where modes got 0/5 and superpowers 3/5. A second trap task built specifically to reproduce that separation failed to — every config passed — and on Opus the original task is 5/5 for everyone. Worse for the finding: re-running an unchanged config on that same task gave 4/5, 1/5 and 2/14 on three different days. A single-day quality figure from this benchmark is a photograph, not a property. The only quality result here measured with both arms on the same day, at n=20, is v7 against v8.
  • On a real project, four of five configurations are indistinguishable ($4.15–$4.82 median) while one config's own runs swing from $2.78 to $9.39. Only superpowers separates, upward: $6.99 and the round's single failed build.
  • Then a sixth configuration was built from those mechanisms rather than chosen from the five. Lea is one SessionStart hook of 226 words — a hard prose budget, a tool-loop rule that spends turns instead of tokens, and an exception that makes contract-checking unlimited. It matches or beats every rival on five Sonnet rounds and three Opus rounds.
  • Then one paragraph of it was rewritten, and that is the largest quality effect on this page. Lea's exception clause said analysis "is unlimited" — a permission a run that never felt uncertain never takes. v8 makes the same check an obligation. Same length, same budget line last, one paragraph different: 13/20 correct against v7's 4/20 on the hard round (Fisher p=0.010), while costing 7% less and finishing 36% faster.

What to do with it. For prose-heavy sessions the terse plugin pair is still a real win over a bare config, and for coding superpowers plus the verification hook looked like it bought correctness that terseness destroys — though that comparison rests on a single Sonnet day, and days move (see the brief). But you no longer have to choose per session: Lea was built to hold both ends at once, and it does, on both models. The rest of this page is the evidence: round by round, with the numbers, the failures, and the mistakes made along the way.

Lea — the configuration the measurements builtLea — ölçümlerin kurduğu yapılandırma

Every round above compares configurations somebody else shipped. Lea is the sixth: not picked from the five, but designed from the mechanisms the matrix exposed, then made to pass the rounds one at a time with a regression re-check after each.

It is one SessionStart hook, 226 words. caveman + ponytail inject roughly 6,000 tokens to do a narrower job. Four rules, and the order between them turned out to matter more than the rules:

A hard prose budget

At most 120 words of explanation per reply, plus whatever code or data the answer needs. Lead with the answer, no preamble, no closing summary.

Each implementation once

Never re-paste unchanged code — name it, state the delta. What you build is exempt: viewport meta, titles, labelled controls, validation and error handling survive every cut.

A tool loop

Read what the task needs, change it, check once, report. No re-running a passed check, no narrating the next call. Turns are the bill.

One exception that overrides the budget

When the code states a contract — a docstring, a spec, a type — checking every clause of it against the implementation is required, and analysis there is unlimited. A green test suite does not count as that check. This clause is the whole design, and rewriting it is the single largest quality effect measured here — see below.

Why the exception clause is the whole design

The matrix found a law and Lea is built around it: in the hard round every wrong fix came in under 1,596 output tokens and every correct one over 1,924, a clean split across 25 runs. The runs that wrote more are the runs that checked the code against its docstring and caught the second, untested bug. Terseness is free everywhere except during a contract audit — which is precisely what the exception protects, and Lea's two remaining Sonnet failures are runs where the exception never fired.

Ordering inside the ruleset moved the numbers more than the rules did, four separate times. Adding the tool-loop paragraph improved tools and pushed prose from 0.0563 to 0.0760; cutting it to one sentence and restating the word budget last recovered it. A four-line "keep correctness basics" block collapsed prose to 0.0879; shrinking it to one sentence and scoping it to built artifacts held the viewport fix at ~15% prose cost instead of 60%.

v8 — the same clause, rewritten as an obligation

v7's failures were read, not guessed. In one of them the agent fixed the visible bug, ran the visible suite, saw green, and closed the task in four words — "All tests pass." 1,266 output tokens, hidden suite 5/8, all three failures on the same expiry boundary it had never looked at. Nothing in the ruleset told it to look: v7 grants permission ("your analysis is unlimited"), and a run that never felt uncertain never takes a permission.

The pooling is balanced by design: five cells per arm on 2026-08-26 and fourteen-to-fifteen on 2026-08-29, both arms on both days, because a quality number belongs to the day it was taken. The prose round was run last for a specific reason — this is the paragraph region that broke prose four times during development, so a version that buys correctness by writing more had to be checked for a prose tax before being recommended. There is none: v8 is cheaper on prose, and all five of its samples land under v7's mean. Read that as "it does not pay for correctness with prose", not as a second win: at n=5 the test gives p=0.22. The tool, website and Opus rounds have not been re-run on v8.

Caveats, stated rather than buried. Prose rounds are n=5 because n=3 lied once — an intermediate version looked 22% better than modes until two more samples killed the margin, since modes' prose cost is bimodal. Tool rounds are n=3. The web and second-hard rounds were deliberately not run on Opus: both are saturated and would not have said anything about Lea. And no figure here is compared against a stored one: the price regime changed between the August matrix and these runs, so every rival was re-measured on the same day as the Lea run it is compared with. Fitting the token prices per era later named the cause: 17-19 August bills at $3.00/$15.03 per M (Sonnet 4.6's list price) and 30 August at $2.00/$10.00 with 0.00% error (Sonnet 5's), with Opus at $5.00/$25.00 throughout. Nothing was repriced - the --model sonnet alias moved from Sonnet 4.6 to Sonnet 5. That rule turned out to cover correctness too, not only money: the same unchanged config re-run on the hard round one day later scored 1/5 instead of 4/5, its median output down from 1,549 to 979 tokens. Read every quality figure on this page as belonging to the day it was taken. The real-project round is now closed: full was re-run on 2026-08-30 and the price regime was verified unchanged since 2026-08-19, giving Lea a median of $3.735 against full's $5.560 — so "Lea is expensive on real work", which its single $8.10 run seemed to suggest, is measured and false. It is also not a ranking: the exact test gives p=0.70, and the pooled within-config spread (SD of log cost 0.397 over 19 runs) means n=37 per arm would be needed to resolve a 30% difference. Any ordering that round has ever produced, this page's included, is sampling noise. One more thing worth stealing: a row's cost and its own token counts must agree. Two rows in 286 billed more than their tokens can buy, because the agent loop restarted mid-cell and the summary JSON described only the last leg — one of them logged 1 turn and 29 output tokens while passing the hidden suite 8/8, which would have read as a cheap, correct win. Development cost $10.48 over 216 API calls, a third of it spent re-measuring baselines.

Her uygulama bir kez

Değişmemiş kodu asla yeniden yapıştırma — adını ver, farkı söyle. Kurduğun şey muaf: viewport meta'sı, başlık, etiketli kontroller, doğrulama ve hata yönetimi her kesintiden sağ çıkar.

Tool döngüsü

Bütçeyi ezen tek istisna

Grading is a hidden suite copied in only after the agent exits; public API only, every assertion traceable to the docstring. The columns that matter are visible_exit=0 with hidden_exit=1: the agent's own tests green, the fix still wrong.

How it unfolded — fifteen daysNasıl ilerledi — on beş gün

The project did not start as a benchmark. It started as two broken hooks, and every round after that exists because a previous answer turned out to be unsafe to believe.

  1. 2026-08-16 · the accident

    Two outages, and a question nobody could answer

    Skills stopped auto-loading. Two separate causes: every SessionStart hook shares one timeout window, so one slow hook cancels the whole batch — and enabledPlugins had drifted out of sync with installed_plugins.json. Both were fixed in an afternoon.

    The uncomfortable part was the question that came out of it: eleven plugins were enabled, and nobody could say what any of them cost or whether it helped. That question is the whole project.

  2. 2026-08-17 · the audit

    Eleven plugins cut to three, then a harness to check the cut

    The token audit came first — measure what each plugin injects before you type anything — and it removed eight of eleven. But an audit only measures cost, never benefit, so the harness followed: five configurations, identical tasks, identical prompts, identical repository copies, and grading the agent cannot reach — a hidden test suite copied in after it exits.

  3. 2026-08-18 · the first answer

    A real project, one run per config — and a headline that did not survive

    Toy tasks answer toy questions, so each config was given a copy of a live seven-language site and told to improve it. The first result read "full is cheapest at $2.90, 60% of bare". It was written down with an n=1 warning attached, and that warning turned out to be the only durable part of it.

  4. 2026-08-19 → 08-24 · the caveats fight back

    A second trap task, a second model, and n=3

    Quality had separated in exactly one round, so a second trap task (Paginator) was written specifically to reproduce that split. It failed to: every config passed. Then every round was re-run on Opus, where the quality difference vanished entirely and the cost ordering reversed in two cells.

    The project round went to three samples per config. The $2.90 headline died there: four of five configs landed inside a 16% band while a single config's own runs ranged from $2.78 to $9.39.

  5. 2026-08-25 · the design

    Instead of picking a config, build one from the mechanisms

    The matrix had exposed three: prose savings come from shorter output, tool-work losses come from a fixed ruleset re-read every turn, and correctness tracks output volume during a contract audit. Lea was written against those three and taken from v1 to v7 in a day, re-measuring every round after every change — which is how the discovery landed that where a sentence sits in the ruleset moved the numbers more than the sentence did, four separate times.

    The same day produced the rule that governs everything since: never compare a new run against a stored dollar figure. Re-running an unchanged baseline gave a different implied price than August's — the regime had moved underneath the whole table.

  6. 2026-08-26 · live, and a warning

    Lea goes live; the headline result fails to replicate

    Opus confirmed the mechanism (−42% prose, −53% on the hard fix at identical correctness), the live config was switched over, and a v8 candidate was drafted by reading the one failing run instead of guessing at it.

    Then the same unchanged config was re-measured on the hard round and scored 1/5 where it had scored 4/5 the day before. Cost barely moved; output volume did. The August lesson about prices turned out to apply to correctness too.

  7. 2026-08-27 → 08-29 · three days of nothing

    A usage limit with no reset time, and a blind five-hour sleep

    The runner hit a 429 whose message carried no parseable reset time and fell back to sleeping five hours — four times over, against a quota that came back inside the hour. Then the machine went down. The queue did not move for three days.

    The fix is in the harness now: probe on a short ladder instead of guessing, because a failed probe costs about fifteen seconds and no tokens, which is strictly cheaper than one long guess.

  8. 2026-08-29 · the decisive round

    v7 against v8, twenty samples each, same day

    At n=5 the two versions had looked like a tie (1/5 against 3/5, p=0.52). At n=20 per arm they did not: 4/20 against 13/20, Fisher p=0.010, with v8 also 7% cheaper and 36% faster. One paragraph, rewritten from permission into obligation.

    The same day turned up a row that would have quietly poisoned it: a cell logging one turn and 29 output tokens while passing the hidden suite 8/8. Its transcript held fifteen turns — the agent loop had restarted mid-cell and the summary JSON described only the last leg. It was caught by arithmetic: a row's cost and its own token counts must agree.

  9. 2026-08-30 · closing it out

    The last unknown, and the switch

    The real-project round finally got a same-day rival, which contradicted the one fear left about Lea: its median is $3.735 against full's $5.560. The same day measured what that round can and cannot say — n=37 per arm to resolve a 30% difference, so none of its rankings were ever real.

    v8 was checked for a prose tax before being recommended (there is none), every report was rewritten, and the live hook was switched to v8. Measurement closed at 232 cells, 0 failed, 286 graded runs.

The shape of it. Five of the nine entries above are a previous conclusion being withdrawn: the $2.90 headline, the quality ranking, the 4/5 hard-round result, the trap task that was supposed to settle things, and every ordering the project round produced. What survived is not the numbers but the rules that killed them — measure the baseline the same day, distrust a quality figure from a single day, and make a row prove its own cost.

Method notes worth reusingTekrar kullanmaya değer yöntem notları

  • Config isolation: --setting-sources project from a directory with no project settings, plus --settings <config>. Note that --setting-sources "" is rejected and silently eats the next argument.
  • Force InvariantCulture before writing any CSV. Under a comma-decimal locale the cost field wrote 0,05 and split the column.
  • Launch long rounds detached, not through an agent tool harness — background runs launched that way were killed twice mid-round.
  • Grade with a hidden suite, and hash the visible tests. Without the tamper check, "all tests pass" includes the runs that edited the tests.
  • Make every row prove its own cost. A run's billed cost and its reported token counts must agree. Two rows in 286 did not, because the agent loop restarted mid-cell and the summary JSON described only the last leg — one of them logged 1 turn and 29 output tokens while passing the hidden suite, which reads as a cheap correct win. Fit the four token prices from a clean day by least squares (they reproduce that day to ~0.15%) and flag any row billed more than 3% above what its own tokens buy.
  • Check the price regime by prediction, not by re-running a baseline. Prices move underneath a long benchmark. Instead of re-measuring a whole rival arm, price a few new runs with an older day's fitted vector: if the prediction lands within a fraction of a percent, the regime held. Three runs and about $0.54 replaced a full re-baseline here.
  • Measure a round's resolution before you rank anything with it. The real-project round's within-config spread is an SD of 0.397 in log cost over 19 runs, which puts the 80%-power sample size at n=37 per arm for a 30% difference. Every ordering that round ever produced was below its own noise floor. One power calculation would have saved three ranking claims.

An invalidated benchmark, kept as a warning

An earlier attempt produced dramatic numbers — 30,379 median input tokens for bare against 167,624 for all three plugins. Reading the actual outputs showed the configs did three different jobs. superpowers-only asked a clarifying question instead of doing the task; modes-only tried to write files, hit permission-denied in -p mode, and retried — and every denied tool call is another round trip re-reading the whole prefix. The input explosion measured permission denials and behavioural divergence, not efficiency.

Always read the outputs before reading the aggregates.

  • Config izolasyonu: proje ayarı olmayan bir dizinden --setting-sources project, artı --settings <config>. Not: --setting-sources "" reddediliyor ve sessizce bir sonraki argümanı yutuyor.
  • Herhangi bir CSV yazmadan önce InvariantCulture zorla. Virgüllü ondalık kullanan bir yerelde maliyet alanı 0,05 yazdı ve sütunu ikiye böldü.
  • Uzun turları detached başlat, agent tool harness'ı üzerinden değil — o şekilde başlatılan arka plan koşuları tur ortasında iki kez öldürüldü.
  • Gizli bir suite ile notlandır ve görünür testleri hash'le. Kurcalama kontrolü olmadan "tüm testler geçti" ifadesine testleri düzenleyen koşular da dahil olur.
  • Her satıra kendi maliyetini kanıtlat. Bir koşunun faturalanan maliyeti ile raporladığı token sayıları birbirini tutmalı. 286 satırın ikisi tutmuyordu: ajan döngüsü hücre ortasında yeniden başlamış ve özet JSON yalnız son bacağı anlatmıştı — biri 1 tur ve 29 output token yazarken gizli suite'i geçiyordu, yani "ucuz ve doğru" gibi okunuyordu. Temiz bir günün dört token fiyatını en küçük karelerle çıkar (o günü ~%0.15 hatayla yeniden üretiyorlar) ve kendi token'larının satın alabileceğinden %3'ten fazla faturalanan her satırı işaretle.
  • Fiyat rejimini baseline koşarak değil, tahmin ederek sına. Uzun bir benchmark'ın altından fiyatlar kayar. Bütün bir rakip kolunu yeniden ölçmek yerine birkaç yeni koşuyu eski günün fiyat vektörüyle fiyatla: tahmin yüzdenin küçük bir kesri kadar tutuyorsa rejim değişmemiştir. Burada üç koşu ve yaklaşık $0.54, tam bir yeniden ölçümün yerine geçti.
  • Bir turla sıralama yapmadan önce o turun çözünürlüğünü ölç. Gerçek proje turunun config-içi dağılımı, 19 koşuda log maliyet için 0.397 standart sapma — %30'luk bir farkı %80 güçle görmek için kol başına n=37 demek. O turun ürettiği her sıralama kendi gürültü tabanının altındaydı. Tek bir güç hesabı üç sıralama iddiasını kurtarırdı.

How the cuts were chosen

~/.claude.json records real usage in pluginUsage and skillUsage. Across 22 startups, seven plugins sat at usageCount: 0. Three of those duplicated a built-in that ships with the CLI anyway, so disabling them cost no capability at all.

security-guidance was disabled for cost, not because it misbehaved

Its hooks fire a 111 KB Python script on every UserPromptSubmit, every edit-shaped PostToolUse, every Bash, and every Stop — six Python spawns inside one second in the log. Outside a git repo it exits early. Inside a git repo the Stop hook runs an Agent SDK security review per turn, billed to the same quota as the session itself. That is the single largest recurring cost in this setup. The on-demand replacements are the built-in /security-review and /code-review.

Trimming the skill list saves nothing — the listing is capped

The whole skill listing costs ~2,588 tokens and is capped by skillListingBudgetFraction (default 1% of the context window, in characters). When the listing exceeds the cap, descriptions are shortened to fit — so removing a skill does not shrink the total, it just lets the survivors keep longer descriptions. Trimming buys triggering accuracy, not tokens.

The resolver reads if (e.type !== "prompt" || e.source === "plugin") return "on" — a plugin-sourced skill short-circuits before the setting is consulted. The only lever on a plugin skill is disabling the whole plugin.

Gotchas that cost real debugging timeGerçek hata ayıklama zamanına mal olmuş tuzaklar

One slow SessionStart hook kills every other one

They share a single timeout window. When it expires the whole batch is cancelled and no hook output is injected — so a slow custom hook silently takes every plugin's activation down with it, and the session looks like nothing was ever installed. Observed: a PowerShell hook took 5738 ms against a 5000 ms budget (hook_cancelled, timedOut: true in the transcript) and three modes went missing at once.

Never put PowerShell in a SessionStart hook — cold start alone is ~2–3 s. Node starts in ~200 ms. Diagnose by grepping ~/.claude/projects/<slug>/<session-id>.jsonl for hook_cancelled versus hook_success.

Enabled ≠ installed

settings.json can list a plugin under enabledPlugins while ~/.claude/plugins/installed_plugins.json has no entry for it — a marketplace refresh dropped two plugins from that registry in one observed case. Symptom: claude plugin list omits the plugin even though its skills still load. Fix with claude plugin install <plugin>@<marketplace> -y.

A stray .md in a plugin's agents/ directory becomes a phantom agent

caveman ships agents/AGENTS.md and agents/CLAUDE.md as contributor docs. Missing YAML frontmatter does not exclude them — they surface in the roster as caveman:AGENTS and caveman:CLAUDE, each spawnable with All tools. Fix by renaming both to .doc.txt. There is no agentOverrides setting, so this is a cache edit and a plugin update restores the files.

A loose skill file silently shadows the plugin version

A stray ~/.claude/skills/<name>/SKILL.md left over from an old manual install overrides the plugin copy even though settings.json looks correct — the plugin shows as installed but behaves wrong. diff it against the cached copy and delete or overwrite the loose one.

Scripted claude -p runs silently lose their flags on Windows

If claude on PATH is a claude.cmd batch shim forwarding with %*, cmd.exe truncates the command line at the first newline inside an argument. A multi-line -p prompt therefore drops every flag after it — --output-format json and --permission-mode both vanish, and the run comes back as prose with every tool call denied. It looks like a permissions bug and is not. Call the real .exe directly from scripts.

/code-review ultra is billed, not configured

It is built into the CLI binary, not supplied by the code-review plugin, so enabling or disabling plugins has no effect on it. A 5-agent Opus fleet takes ~5–10 min and costs $5–$25 per run, charged to extra usage credits. It appears and disappears with credit state, not settings: when ~/.claude.json shows cachedExtraUsageDisabledReason: "out_of_credits", the option is simply hidden and there is no toggle to flip.

Yavaş tek bir SessionStart hook'u diğerlerinin hepsini öldürür

Tek bir timeout penceresi paylaşıyorlar. Süre dolduğunda tüm grup iptal edilir ve hiçbir hook çıktısı enjekte edilmez — yani yavaş bir özel hook, her plugin'in aktivasyonunu da sessizce yanında götürür ve oturum hiçbir şey kurulmamış gibi görünür. Gözlenen: PowerShell tabanlı bir hook 5000 ms bütçeye karşı 5738 ms sürdü (transcript'te hook_cancelled, timedOut: true) ve üç mod birden kayboldu.

SessionStart hook'una asla PowerShell koyma — soğuk başlangıç tek başına ~2–3 sn. Node ~200 ms'de açılıyor. Teşhis: ~/.claude/projects/<slug>/<session-id>.jsonl içinde hook_cancelled ile hook_success aramak.

Etkin ≠ kurulu

settings.json, enabledPlugins altında bir plugin'i listelerken ~/.claude/plugins/installed_plugins.json içinde ona ait kayıt olmayabilir — gözlenen bir vakada marketplace yenilemesi iki plugin'i o kayıttan düşürdü. Belirti: skill'leri hâlâ yüklenmesine rağmen claude plugin list plugin'i göstermiyor. Çözüm: claude plugin install <plugin>@<marketplace> -y.

Bir plugin'in agents/ klasöründeki başıboş .md, hayalet agent'a dönüşür

caveman, agents/AGENTS.md ve agents/CLAUDE.md dosyalarını katkı dokümanı olarak gönderiyor. YAML frontmatter'ın olmaması bunları dışarıda bırakmıyor — listede caveman:AGENTS ve caveman:CLAUDE olarak, her biri All tools ile spawn edilebilir şekilde çıkıyorlar. Çözüm: ikisini de .doc.txt olarak yeniden adlandır. agentOverrides diye bir ayar yok, yani bu bir cache düzenlemesi ve plugin güncellemesi dosyaları geri getirir.

Başıboş bir skill dosyası plugin sürümünü sessizce gölgeler

Eski bir elle kurulumdan kalan ~/.claude/skills/<ad>/SKILL.md, settings.json doğru görünse bile plugin kopyasını geçersiz kılar — plugin kurulu görünür ama yanlış davranır. Önbellekteki kopyayla diff'le, sonra başıboş olanı sil veya üzerine yaz.

Scriptli claude -p koşuları Windows'ta bayraklarını sessizce kaybediyor

PATH üzerindeki claude, %* ile yönlendiren bir claude.cmd batch shim'iyse, cmd.exe komut satırını bir argümanın içindeki ilk satır sonunda keser. Çok satırlı bir -p promptu bu yüzden kendisinden sonraki tüm bayrakları düşürür — --output-format json ve --permission-mode ikisi de kaybolur, koşu düz metin olarak döner ve her tool çağrısı reddedilir. İzin hatası gibi görünür ama değildir. Scriptlerden doğrudan gerçek .exe dosyasını çağır.

/code-review ultra faturalıdır, yapılandırma değildir

CLI binary'sinin içinde gömülü, code-review plugin'inden gelmiyor, yani plugin açıp kapatmak onu etkilemiyor. 5 agent'lı bir Opus filosu ~5–10 dakika sürüyor ve çalıştırma başına 5–25 dolar, ekstra kullanım kredisine yazılıyor.
